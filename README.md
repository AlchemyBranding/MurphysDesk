# Murphy's Desk

A Year 6 maths and English mechanics app she can sit down and use on her own.

The app supplies the work, marks it, decides what comes next, and tells you what
keeps going wrong. You do not write questions and you do not mark anything.

---

## What it does, and what it deliberately does not

**Does**

- Generates every question from a **parameterised template where the answer is computed by code**. The numbers re-roll on every retry, so a mastery gate cannot be memorised, and there is no bank of items to run out of. This is the Sparx mechanic.
- Teaches before it tests, with a **fading ladder**: worked example, then completion problem, then on her own. Promotion after two consecutive correct, demotion after two consecutive wrong. The demotion path matters more than the promotion path.
- Gives a **misconception-specific explanation on every wrong answer**, because every distractor is generated by applying a named error rather than being a random wrong number.
- **Gates progression** on four conditions at once, not a streak. See below.
- Schedules retention with **FSRS-6 at objective level**, so October is still true in March.
- Shows you a **misconception leaderboard**: the same error firing across three different topics is one conversation, not three.
- **Parks** an objective after two failed gates and tells you, rather than grinding her against a wall.
- Reports **rising speed with falling accuracy** as a stop signal.

**Does not**

- No points, no badges, no leaderboards, no streaks, no coins, no lives.
- No total score, no grade, no level, no rating of her.
- No comparison to anyone: not classmates, not year-group expectations, not her brother.
- Nothing on the wall ever comes off.
- No LLM anywhere in the runtime. Every explanation was written and reviewed once, offline.
- No extended writing. Nothing currently grades a ten-year-old's composition reliably, so the app does not pretend to.

## The gate

An objective is only offered to the gate when she is working independently, has
four in a row right, and the belief estimate is already at threshold. The gate is
meant to confirm something we already think is true, not be a lottery she keeps
losing.

It then passes only if **all four** hold:

1. **Threshold** — at least 5 of 6 correct.
2. **Belief** — Bayesian knowledge tracing `p(known) ≥ 0.95`, or `0.98` for the foundational objectives everything else depends on.
3. **Construction** — the sixth item is a typed answer wherever one exists, so it cannot be passed by eliminating options.
4. **Integrity** — no answer arrived in under three seconds. Any that did voids the sitting rather than failing it.

Why not a streak: Khan Academy gated on ten-in-a-row, published why they
abandoned it, and replaced it with a probability estimate over the whole history.
Streaks produce false positives (thirty problems to assemble ten) and false
negatives (nine right, one typo, back to zero).

The parameters live in `src/lib/bkt.ts`, in one place, so they can be argued with
rather than buried. They are conventional literature values, **not fitted to
Murphy**. Fitting needs hundreds of learners; with one you would be fitting noise.

## Setting it up

### 1. Supabase

Create a project, then in the SQL editor run `supabase/schema.sql` in full.

Then in **Authentication → Users**, add two users with email and password: one
for you, one for her. Copy their user ids and run the insert at the bottom of
`schema.sql` with the ids filled in.

Row level security is on for every table. A learner can only ever see her own
rows; a parent can read the rows of learners in the same household.

### 2. Environment

```bash
cp .env.local.example .env.local
```

Fill in `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` from
Supabase → Project Settings → API.

### 3. Run

```bash
npm install
npm run dev
```

Deploy to Vercel and add the same two environment variables there.

**One Supabase gotcha worth knowing:** free-tier projects pause after a week of
inactivity, and half-terms and holidays will trip it. Either take Pro, or set a
keep-alive cron.

### 4. On her device

Sign in as her and stay signed in. She should never see a login screen.

## Checking it before she does

```bash
npm run check-content   # property test, 400 seeds per template
npm run simulate        # drive the engine with a simulated learner
```

`check-content` generates roughly twenty thousand questions and asserts, for
every one of them:

- the app's own answer marks as correct (the round trip)
- no distractor marks as correct
- **every incorrect option carries a named misconception**, which is Craig Barton's rule 4 as a build-time assertion
- no duplicate options, no empty labels, nothing undefined leaked into the text
- the prerequisite graph is acyclic and every objective has templates

`simulate` runs three synthetic learners at 90%, 70% and 40% accuracy through
forty sessions each and checks the engine terminates, gates open, a weak learner
gets parked rather than ground down, and nothing deadlocks.

**Neither of these tells you the maths is right.** They tell you it is
self-consistent. Before any new template ships, work five random instances of it
by hand, on paper. `npm exec tsx scripts/sample.ts 5` prints them for you.

There is also `/preview`, which runs the real question components with no
database attached, so you can look at every template and try the rungs.

## Adding content

Everything lives in `src/content`:

- `objectives.ts` — the spine. What she is learning, in what order, what she can say when she has it, and the named misconceptions.
- `maths.ts`, `english.ts` — the templates.

A template is a function from a seeded random number generator to a question. The
important rule:

```ts
answer: p => Rational.add(Rational(p.n1, p.d1), Rational(p.n2, p.d2)).simplify()
```

**Exact rationals, never floating point.** `0.1 + 0.2 !== 0.3`, and a child should
never be marked wrong for that.

Distractors are generated by applying a misconception, not invented:

```ts
traps: [
  { value: `${n1 + n2}/${d1 + d2}`, misconceptionId: 'add-both' },
  { value: `${n1 + n2}/${d1}`,      misconceptionId: 'kept-first-denominator' },
]
```

`week` on each objective is the fixed pace. Mastery gates the ordering and the
repetition; the week gates overall progress, because the EEF evidence on mastery
learning turns negative when it is purely self-paced. You move the week on from
the dashboard.

## Where the content came from

- **Objectives**: England Year 6 programmes of study and the DfE ready-to-progress criteria, both Open Government Licence v3.0. Wales publishes no content list, so this is the only granular, testable specification available anywhere in the UK.
- **The Year 5/6 spelling word list**: English Appendix 1, OGL. Wales publishes no word list at all, which makes it one of the clearest gaps against what an English secondary assumes.
- **The explanation videos**: Oak National Academy, Open Government Licence v3.0, on the twelve objectives where the procedure only holds up once the concept underneath it does. Attribution is a licence condition and stays on the card. Oak serve video from Mux under a signed playback policy, so these open Oak's own page in a new tab rather than embedding; embedding would need an Oak API key.
- **Everything else** was written for this app.

## Honest limits

1. **Marking happens in the browser.** The correct answer is in the JavaScript. This is a private family app and reading the source to cheat is not a threat model worth engineering against; it is also a much harder way to get the answer than just thinking.
2. **The teach rungs do not move the belief estimate**, only the ladder. Copying a worked answer is a reading check, not evidence of knowing something.
3. **A gate measures performance, not learning.** Those come apart. The app says "she can do this today" at the gate and only earns the wall card there; the delayed retention checks are what actually confirm it a month later.
4. **The spelling test needs speech synthesis.** Where it is unavailable the note gives the first letter and the length, which is weaker.
5. **The videos are a link away, not in the app.** Oak's playback is signed, so she leaves the session to watch one. That is a real hole in the design, and the fix is an Oak API key.
6. **English here is mechanics only**: spelling, punctuation, grammar. Composition is not in scope and should not be.
